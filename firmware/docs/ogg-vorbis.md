# Vorbis playback and decoder program

The image contains a separate core-1 Vorbis program built from pinned Xiph Tremor lowmem source. The player selects the Vorbis source for Ogg input. File opening, configuration, normalized duration, cropped starts and seeking have native reference tests and integrated Cortex-M3 player scenarios. Physical decode headroom and listening on the owner’s player remain to be measured. Source and BSD notices are in `third_party/tremor`; Gnarlyr remains GPL-3.0-or-later.

`device/vorbis_decoder` accepts three configuration packets, then audio packets. Input may have two spans, allowing a compressed packet to wrap in the shared ring without a copy. PCM goes into caller-owned planar signed 32-bit arrays at 24-bit scale. Mono and stereo, 8–192 kHz header rates and up to 4,096 output frames are bounded before output. A caller must provide capacity for the configured long block. Actual hardware throughput across those rates remains to be measured.

The workspace is a caller-owned 64 KiB block. Permanent setup storage grows from its beginning; temporary work grows from its end and restores its cursor at each function exit. Neither can cross the other. Allocation, multiplication and alignment bounds are checked before returning storage. Individual frees are no-ops; initialization resets the whole workspace for a new stream. The guarded wrapper exits on exhaustion before unchecked upstream allocation users can dereference a null result. Header parsing stops at missing bits; malformed codebook dimensions and cleanup arrays have regressions. Normal audio end-of-packet handling follows Tremor.

The wrapper serializes entry to the private codec allocation hooks; a second active decoder cannot replace the current failure guard. Native tests use the host jump buffer; Cortex-M3 uses GCC's built-in five-word checkpoint in the caller's decoder state. Header/decode failure releases the active binding and marks the decoder failed. A new initialization is required after failure.

`core1/core1_vorbis.ld` preserves the existing 128 KiB instruction bank and a 16 KiB stack reserve. The program has 32,952 bytes of BSS including its private 32 KiB packet buffer, below the reserved stack. Its 64 KiB input ring starts at `0x01040000`; the 64 KiB workspace follows at `0x01050000`. PCM uses the existing two shared output slots. A static assertion keeps output blocks within those slots, and the stream avoids copying channels already in their destination slot.

The record protocol is little-endian length (4 bytes), flags (4 bytes), granule (8 bytes), then packet payload. Flags 1 and 2 mark first/last packets. A zero-length record with flag 4 ends the virtual stream; an empty audio packet is refused. Payload capacity is 32 KiB. Headers are consumed and released as they configure the decoder, so setup does not wait for a PCM block before returning input space. Failed reads wait for more ring data without advancing the packet cursor. A complete compressed packet is copied into private storage and its generation is rechecked before decode; switching tracks can refill the producer ring without changing a packet the old decoder is still using.

`device/vorbis_stream` converts checked Ogg files to that record protocol using a caller-owned 32 KiB packet buffer. Reads are sequential and may cross any header/body/packet boundary. It validates the three Vorbis packet signatures and their order. Comment payloads have their framing, checksum, signature and minimum packet length checked, then are discarded and replaced by a minimal empty comment packet; decoder setup therefore never allocates embedded artwork or other unused tags. The library metadata reader remains responsible for interpreting tag fields. Identification, setup and audio packets retain the 32 KiB transport limit.

The virtual stream emits an explicit end record only after a checked Ogg end-of-stream page and all three headers. It pads subsequent ring-fill reads with zeros. Storage failures, damaged pages, oversized audio and invalid headers mark a sticky error and return failure, never a successful end record. Restarting the adapter resets that error; invalid caller offsets and buffer bounds leave the current position untouched. A failed read may have copied a prefix into its destination; the caller must discard that request, as `Core1Source` does before publishing ring input.

For a stream starting at zero, PCM positions begin at zero and known granules anchor output positions. A nonzero first-sample request discards unanchored output until a granule is known; the file-side seek controller must choose sufficient preroll and apply the requested sample trim. This transport facility does not implement file seeking by itself.

The program is stored at image offset `0x260200`, with an `EC1M` header containing length and CRC. Its payload capacity is `0x1FC00`, ending at the existing FLAC program slot. MP3, FLAC and M4A keep their offsets. Font/language allocation excludes the new bank. `board/core1.c` selects and checks it through the existing core-1 loader; no startup path or storage write range is added.

Native and Cortex-M3 tests decode independent Xiph fixtures at 8 kHz mono and 44.1/48 kHz stereo, compare every sample with a maximum difference of two 16-bit sample units, and require exact final lengths. They also cover ring wrapping, workspace exhaustion, malformed setup, oversized packets and a track change during decode that must publish only the new generation. The ARM test keeps a guard at the reserved stack boundary. `tools/vorbis_fixture.py` regenerates the synthetic fixtures through the independent Xiph reference libraries; normal tests use checked-in fixtures.

Native file-adapter tests decode all four reference fixtures through fragmented records and a stream with a valid 70,000-byte comment. They compare PCM to Xiph reference output, check bulk ring-fill requests against independently assembled records, and distinguish failed storage or malformed input from a clean end. Packet-prefix and file-adapter tests pass with AddressSanitizer and UndefinedBehaviorSanitizer. The source opener supplies the configuration handshake, file seek and start trim described below.

`device/vorbis_track` probes the identification/configuration signatures through the checked packet reader, checks channel/rate/block limits and the setup-packet transport cap, then finds a checked final granule near the file end. A missing final granule is refused rather than replaced with an earlier page position. The current sample-position protocol uses 32-bit positions; larger endpoints are refused. Failed probes preserve the caller's track metadata.

Seeking bisects byte ranges and searches at most one maximum Ogg page length from each midpoint. It selects a non-EOS marked page at or before the target; this leaves a preceding granule for Tremor to judge the final packet. Unknown-granule continuations are followed with serial and sequence checks. `ogg_stream_seek` replays the configuration headers before resuming that page. Early targets and single-audio-page files start from the original stream start; core 1 must receive first-sample zero for that case, with the source/engine applying the requested target trim. Other starts wait for their first known granule. Failed seeks preserve the output offset.

Native tests drive the actual `Core1Vorbis` decoder through this file stream and compare every retained sample against independent Xiph output at page boundaries, immediately after boundaries, near the final sample and at/beyond the endpoint. They also cover single-page speech, corrupt/failed probes and a large synthetic paged file whose distant seek reads less than half the file. Long chirps, cropped first pages and origin-shifted streams cover the additional first-page accounting cases.

After the third header, core 1 publishes `VorbisModes` (short/long block sizes, mode count and a two-word long-mode mask) before a release fence and the configuration generation. These fields follow the existing 96-byte stream-control layout; static offset assertions preserve the slot fields used by every decoder. A core-0 caller must observe the matching generation before reading the snapshot.

`vorbis_track_origin` scans one-byte audio-packet prefixes from a copy of the post-header packet cursor. It counts overlap samples using those validated modes until the first known granule, computes a nonnegative PCM origin and subtracts it from the raw endpoint. The caller's cursor and track remain intact after failed reads or invalid packet modes. Header-only prefill uses `header_bytes` and stops before the first audio record. A normalized seek adds the origin when comparing raw page granules.

An optional zero-payload record with flag 8 carries the 32-bit PCM origin after configuration and before audio. Core 1 subtracts it from known audio granules before synthesis and sample-position anchoring. Duplicate, late, mixed-flag, nonempty or unrepresentable origin records fail. This keeps duration, seek targets, decoded lengths and published positions on one timeline. Native and Cortex-M3 regressions compare the origin-shifted and cropped-start streams with independent Xiph PCM; every published PCM block remains contiguous. The player/source opening handshake uses these published fields as described below.


`core1_open_ogg` opens the file through the existing caller-owned file interface, probes it and supplies only `header_bytes` to the compressed ring. Core 1 configures Tremor and publishes its mode snapshot without publishing PCM. A bounded player wait fills those headers, refuses decoder/storage failures and observes the matching configuration generation. The source computes the PCM origin and normalized seek, publishes `first_sample`, then releases the remaining virtual stream. `vorbis_start_generation` follows the configuration generation at offset 120; core 1 observes it before decoding its first audio record. This prevents audio from being decoded with a provisional seek anchor.

The source discards every complete preroll block before the requested sample and trims the first retained block. This applies to early seeks that must begin at the original audio start as well as page-based seeks. Its reported codec is Vorbis, its lossy stream depth is unspecified and its PCM frames use 24-bit scale. Failed opening preserves the caller's track information, closes the file and stops the generation. Storage failure after setup or during playback remains an error. Reopening requires a new matching configuration generation. Refill discards full PCM slots from older generations before configuration can stall behind them; a regression opens a second stream with both old slots still full. The bounded wait accepts a decoder error only from the current generation, so a late old-core result cannot abort a new setup. An ARM regression injects that result after refill and before the wait checks it.

The file adapter and source opener reside in audio module 6, sharing the 8 KiB audio bank with module 5. Their mutable state lives in the existing decoder union and resident source; module 6 has no BSS. The resident dispatcher checks the loaded entry before reads. Both modules include the same resampling kernel, allowing a converted-rate track to keep the current kernel after the file adapter closes. The full engine drains pending output before a new file operation replaces that bank.

Native source tests decode reference files through actual opening and refill calls, including 7-byte refill budgets, mono speech, cropped starts, origin shifts, seeks and endpoint clamps. ASan and UBSan cover the source, seek controller, file records, decoder and shared-stream consumer. Integrated ARM tests connect the main player and the real Vorbis core-1 program with cooperative shared-memory scheduling. They exercise converted WAV → Vorbis → WAV, slot fallback, saved-position startup, pause/resume and refusal of two damaged file modules. This scheduling model establishes functional behavior, not real-time hardware performance.
