Docs/Recovery

Full-size ECHO · macOS reference

Install once. Keep a way back.

Recovery mode lets a computer reach the player before its normal software starts. Use it when a player won’t start or no longer shows its drives over USB. A player that starts installs Gnarlyr, or goes back to FiiO, by copying one file.

This guide uses the full-size ECHO: see the player on Amazon ↗ or AliExpress ↗.

On this page

  1. Prepare the files
  2. Enter recovery mode
  3. Check & back up
  4. Install Gnarlyr
  5. Restore FiiO

Prepare before connecting.

The ECHO stores firmware in two slots. This procedure backs them up, then writes and checks the second slot before touching the first.

  • Charge the full-size ECHO and copy any music or personal files you want to keep to your computer.
  • Have the complete GNARLYR.img, its supplied checksum and FiiO’s full-size ECHO image ready. For Gnarlyr 1.0, use the matching release guide when published; developers can build from their checkout.
  • Use the patched rkdeveloptool-echo, a USB data cable connected directly to the computer, and a paperclip. Build the matching recovery tool on macOS →
  • Keep the image, backups and readbacks in a work folder outside the source repository. Run the commands below from that folder, with the recovery tool available on your PATH.

These slot addresses are for the full-size ECHO. Keep the cable connected and the computer awake during writes. If a check fails, stop before the next write.

Enter recovery mode.

This mode is called maskrom. The screen stays black while the computer talks to the chip directly.

  1. Unplug USB and press the recessed RST button with a paperclip.
  2. Hold every button except Power: Play, Menu, Back and the volume rocker.
  3. Connect USB while holding the buttons. Release them after two to three seconds.

A player running Gnarlyr can skip the paperclip. Plug the cable into the computer, then hold Power and Vol+ together for about 5 seconds, whether the player is on, showing a message or switched off on the dark charge screen. The screen goes black in recovery mode; let go. Alternatively, put a file named MASKROM.REQ containing the text MASKROM REQ at the top of internal storage, eject and restart the player.

Check the connection. Wait two seconds after the first command lists the device before running the second.

rkdeveloptool-echo ldrkdeveloptool-echo td

Continue only when ld shows Maskrom, the device is 2207:262d, and td says Test Device OK.

Check the layout. Save the original.

Read both slot headers to confirm the layout, then make two independent backups. Matching backups give you a consistent copy to keep.

rkdeveloptool-echo rl 0 1 head1.binrkdeveloptool-echo rl 81920 1 head2.binxxd -s 0x1f8 -l 8 head1.binxxd -s 0x1f8 -l 8 head2.bin

Both headers must show RKnanoFW at offset 0x1F8. A different result means this layout has not been confirmed; stop here.

rkdeveloptool-echo rl 0 163840 backup-a.binrkdeveloptool-echo rl 0 163840 backup-b.bincmp backup-a.bin backup-b.bin

cmp prints nothing when the files match. Keep both backups until the new firmware starts and your saved state has been checked. Choose either the Gnarlyr installation or FiiO restoration route below.

Install Gnarlyr.

This writes the image’s first 5 MiB into each firmware slot, the same bytes FiiO’s updater writes from a copied ECHOECHO.IMG.

Complete preparation, connection and backup above first. Check GNARLYR.img against its supplied checksum, then prepare the slot file:

shasum -a 256 GNARLYR.imghead -c 5242880 GNARLYR.img > slot.binshasum -a 256 slot.bin

Write and check slot 2

rkdeveloptool-echo wl 81920 slot.binrkdeveloptool-echo rl 81920 10240 readback2.bincmp slot.bin readback2.bin

Continue only if the comparison prints nothing.

Write and check slot 1

rkdeveloptool-echo wl 0 slot.binrkdeveloptool-echo rl 0 10240 readback1.bincmp slot.bin readback1.bin

After both full readbacks match, restart:

rkdeveloptool-echo rd

The tool should say Reset Device OK. Check Settings → About in Gnarlyr, then let the first library scan finish. Continue with music setup →

Restore FiiO’s firmware.

Restoring stock uses the complete official ECHO image in both slots. Use this route instead of the Gnarlyr slot-file steps.

Complete connection and backup above. Get the full-size ECHO’s ECHOV200.IMG from FiiO’s firmware page. The V2.0.0 image is 39,845,892 bytes and has this SHA-256:

c6a3b6c86b141c0a428771f8a611fbd44cc12d561acb033a98640b0bf24f8d57

Check its size and checksum before writing. If the normal internal drive is accessible, remove any pending update images before entering recovery so the restored player does not install one at startup.

Write and check slot 2

rkdeveloptool-echo wl 81920 ECHOV200.IMGrkdeveloptool-echo rl 81920 77825 readback2.binhead -c 39845892 readback2.bin | cmp - ECHOV200.IMG

Continue only if the comparison prints nothing.

Write and check slot 1

rkdeveloptool-echo wl 0 ECHOV200.IMGrkdeveloptool-echo rl 0 77825 readback1.binhead -c 39845892 readback1.bin | cmp - ECHOV200.IMG

When both readbacks match, restart:

rkdeveloptool-echo rd

Check Settings → About in FiiO’s firmware. If the screen stays black after the reset, unplug USB, press RST, then press Power.

If a step fails.

A matching readback is the signal to continue. Resolve a connection or comparison problem before moving to the next slot.

  • No device: repeat the button sequence with a data cable and a direct computer port.
  • Loader instead of Maskrom: check that you built the patched ECHO tool.
  • A command hangs for about a minute: press Ctrl+C, unplug, press RST, enter maskrom again and restart from the connection checks.
  • A readback differs: write that slot again and compare it. Do not restart until both slots match.
  • A write fails twice the same way: try another port, cable or computer.

Use only the commands shown here. Do not run db, ul, ef, wlx or tools/loaders for another ECHO model. The checkout’s firmware/docs/device-install.md and firmware/docs/device-recovery.md are the source references for this procedure.
