From music file to headphone signal.

The processor reads files and runs the menus. A digital-to-analog converter, or DAC, turns decoded samples into the electrical signal used by the headphone output.

Processor platformRockchip RKnano with two ARM Cortex-M3 cores: one runs the player; the other runs a decoder loaded when needed.
Audio chip ACS43198 · bus address 0x30 (7-bit)
Audio chip BCS43198 · bus address 0x33 (7-bit)
Chip identification · 4 GB unitID 43 19 80 · revision A1 · subrevision 06
Audio transportI2S carries audio samples to the DACs. DMA transfers samples from memory without making the main loop copy each one.
EQSoftware EQ runs on the main processor. The CS43198’s own digital filters and gain controls are separate.

Read the Cirrus Logic CS43198 documentation for chip details, or FiiO’s specifications for player ratings.

How the chip identification was read

Read-only registers 0x010000, 0x010001 and 0x010002 supplied the ID. Registers 0x010004 and 0x010005 supplied revision and subrevision. The driver’s wire-format addresses 0x60 and 0x66 correspond to 7-bit addresses 0x30 and 0x33.

Both chips on a 4 GB ECHO returned 431980 A1.06. A1.06 identifies their hardware revision.

Screen, backlight and buttons.

The display stores its own picture. The processor sends changed areas, helping the interface fit within the ECHO’s memory budget.

  • Display protocol. The driver uses an ST7796S-style command set and 16-bit RGB565 pixel transfers. Its startup sequence matches the stock firmware’s 24 display-initialization commands and their data.
  • Landscape and portrait. Stock’s landscape window has a 49-row offset. Portrait changes the orientation bits and applies that offset to the other axis.
  • Backlight. A 25 kHz PWM signal on GPIO2.4 controls brightness by rapidly switching the backlight on and off.
  • Buttons. Volume, Play, Menu and Back share a resistor ladder. An ADC, a voltage-measuring input, reads the different voltages so the player can identify each button. Power has its own input.

USB, power and Bluetooth.

USB storage exposes the music drives to your computer. USB mode lets you return to charging or playing on USB power, or connect to the computer again, on the same cable. The firmware also provides a USB DAC audio path; a separate module handles Bluetooth headphones.

  • USB controller. A DesignWare USB 2.0 OTG controller. Storage can negotiate high speed and retry at full speed if the first connection does not become usable.
  • Mode selection. Open USB mode from Home or Settings. Eject both drives before leaving storage, then choose Player without unplugging. The current track, position and queue are kept.
  • Separate drives. Internal storage and an inserted microSD card appear as separate drives. Eject every drive present at connection to return storage to the player.
  • Audio mode. The firmware’s USB Audio Class 1.0 path offers 16- or 24-bit audio at 44.1 or 48 kHz, with a separately remembered DAC volume.
  • Cable detection. GPIO2.0 controls taking power from USB and GPIO0.14 controls charging. Gnarlyr keeps these power-control signals in sync with the cable state.
  • Bluetooth module. A separate module handles wireless audio. The processor controls it with short commands over UART1 at 115,200 baud. FiiO specifies SBC transmission to headphones.

Storage and working memory.

Storage keeps music and firmware when the player is off. RAM holds working data while it runs. Firmware has two separate storage slots; the updater writes and checks the second before writing the first.

Internal storageeMMC with two firmware slots, a SAVE area and the user’s FAT32 volume. The microSD card is separate.
Main working RAMCore 0 data window: 0x03004000–0x0304C000.
Decoder RAMCore 1 region: 0x01000000–0x0105FFFF · 384 KiB.
Shared high RAM0x0307A000–0x0309EFFF · 148 KiB, used for overlays and temporary work.
Main code location0x03050000. Extra screens and USB work can load into a bounded module region.
Battery readingADC channel 0 measures the rail powering the player. On battery this reflects the cell; USB power can lift the rail above the cell voltage.

Gnarlyr therefore distinguishes Charging, Charged and USB power. It avoids presenting a USB-powered rail reading as the battery’s voltage.

These working regions come from the firmware map and stock-code analysis; they do not specify the ECHO’s total RAM capacity.
