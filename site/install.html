What is on your player now?

The first switch from FiiO’s software is a recovery installation. Once Gnarlyr is running, its own updater handles later builds from a copied file.

FiiO stock firmwareStart with first installation through recovery.
Gnarlyr 1.0 or laterUse the manual USB update. Developer builds can also use the computer-assisted update loop.
An older custom buildUse the migration notes to match its image identity before updating.

Gnarlyr image: GNARLYR.img. Use this filename for Gnarlyr updates. FiiO’s ECHOV200.IMG is the stock restore image.

Build from your checkout.

These build steps are for owners of a Gnarlyr source checkout. Run the commands on macOS from its root folder. The build wrapper prepares an image on your computer; it does not install it on the player.

  • Python 3.14 and firmware/tools/requirements.txt.
  • Build tools: CMake, SDL2, FFmpeg, clang-format and the Arm GNU cross-compiler.
  • Scratch storage: mount a disposable build-output volume at /Volumes/Scratch. It keeps generated files separate from your backed-up source. The wrapper creates firmware/build as a link to the checkout’s Scratch output.
Set up the build environment

Create a Python virtual environment on Scratch. Set ECHO_VENV to that folder and ECHO_ARM_BIN to the folder containing arm-none-eabi-gcc. Full prerequisite instructions are in the checkout’s README.md.

Build the release image 

python3 tools/firmware.py setuppython3 tools/firmware.py build --preset release

Record its SHA-256 

shasum -a 256 firmware/build/release/GNARLYR.img

The output is firmware/build/release/GNARLYR.img. SHA-256 is a fingerprint of the file: comparing fingerprints tells you whether the copy is identical.

First, give the player its new software.

Recovery mode lets a computer install Gnarlyr directly into the firmware area. Use it for the first switch from FiiO’s software.

  1. Build the image and record its fingerprint. Follow the build steps above to create GNARLYR.img and record its SHA-256 before starting recovery.
  2. Prepare the player. Back up your files, charge the ECHO, and keep the official full-size ECHO recovery image with your recovery tools.
  3. Enter maskrom recovery. Maskrom is the chip’s built-in recovery mode. Unplug USB, press RST with a paperclip, hold every button except Power, then connect USB while holding them. The computer should identify 2207:262d, and the patched recovery tool should pass its connection test.
  4. Verify the layout and save a backup. Follow firmware/docs/device-install.md and firmware/docs/device-recovery.md in your checkout. Check both firmware-slot headers, then read the original firmware twice and compare the complete backups.
  5. Install with readback. The recovery procedure writes the second slot, reads the entire slot back and compares it with the prepared image. Only then does it write and verify the first slot.
  6. Start Gnarlyr. Restart the player, check the firmware identity in About, and let the first music and artwork scan finish before reconnecting USB.

Use the exact-model commands in those guides. The initial recovery install uses the image’s first 5 MiB; ordinary later updates use the complete GNARLYR.img file.

FiiO’s file-copy updater accepts official ECHOVnnn.IMG images. Use recovery to install GNARLYR.img for the first time.

Next time, copy a file.

Gnarlyr already knows how to install its next build. You copy the image onto internal storage, check it, then eject the drives so the player can take over.

  1. Connect in Storage mode. Internal storage appears as a drive, plus a separate microSD drive when a card is inserted.
  2. Copy and check. Put the complete GNARLYR.img at the top level of internal storage as its only update file. Verify the copy before ejecting. On macOS, use cp -X to copy without metadata sidecars and remove any ._GNARLYR.img sidecar from the drive.
  3. Eject every mounted ECHO drive. Wait for the player to check the image, show installation progress and display “Update installed.” Keep the cable connected during the write.
  4. Restart into the new build. Unplug USB, hold Power for two seconds to switch off, then turn the player back on. Check the firmware version in About. The updater removes the image after a successful installation.

Check the copied image · macOS 

shasum -a 256 "/Volumes/YOUR_ECHO/GNARLYR.img"

Replace YOUR_ECHO with the internal drive’s actual name. Compare the result with the build checksum above. The microSD drive is for music; the updater reads the image from internal storage.

Eject first. Unplug when the player is ready.

Eject tells the computer to finish writing and gives the storage back to the player. That is when Gnarlyr can inspect the update file and begin installing it.

  • Eject is the handover. While the computer has the drives, it owns file access. Ejecting every drive present at connection returns storage to Gnarlyr and starts the update check.
  • The cable can stay connected while it writes. The end of a storage session and removal of the cable are separate events. Wait for “Update installed” before unplugging.
  • The new USB code starts with the new firmware. USB and updater code load from the image into a shared memory region. Restarting after installation ensures the running firmware and its USB module match.
  • Connection handling follows cable power. Gnarlyr keeps USB power control in sync with the cable state. The stack can retry at full speed if its first high-speed connection does not become usable.

For everyday music copying, eject every drive before unplugging too. Gnarlyr then checks whether the music changed and rescans when needed.

Let the computer handle the repeat steps.

When you are testing developer builds, the macOS helper can do the copy, verification, eject and restart round trip and report which build came back.

Build a developer image with python3 tools/firmware.py build --preset device, then use the matching checkout’s helper:

Install and request a restart 

python3 tools/echo_debug.py install firmware/build/device/GNARLYR.img --restart

The helper checks the copied file, asks the developer firmware to restart after installation, ejects the player’s drives, waits for it to leave and return on USB, and reads back the running build. Leave the cable connected for this loop.

Ordinary manual updates use the unplug-and-Power sequence above. Automatic restart is a developer-build workflow.

Match the updater to the build you have.

A custom updater checks the image’s identity as well as its name. Older firmware may need a bridge or the recovery route before it can accept a current Gnarlyr image.

For a pre-release or older custom build, use the update instructions supplied with that build. Earlier Gnarlyr development images used FRSHBS.IMG; Doublesharp Echo used DBLSHARP.IMG. Those names describe development history, not public release versions.

The documented Doublesharp Echo route first installs the bridge-frshbs build, then moves to the later firmware. firmware/docs/device-install.md explains which checkout and helper to use at each step. For other starting builds, use the exact-model recovery installation.

An image contains an internal firmware identity too. Renaming the file cannot make an incompatible updater accept it.

Keep a way back to the original software.

Recovery mode belongs to the chip, so it remains the separate route for reinstalling stock firmware when the normal player interface cannot be used.

Keep the full-size ECHO’s official ECHOV200.IMG and the exact-model recovery instructions from your checkout. The official V2.0 image is 39,845,892 bytes, with SHA-256: 

c6a3b6c86b141c0a428771f8a611fbd44cc12d561acb033a98640b0bf24f8d57

For a player that does not start, follow firmware/docs/device-recovery.md to restore the official image through maskrom, checking each complete slot readback.

A running Gnarlyr also recognizes the official ECHO image through its updater. Follow the checkout’s return-to-stock instructions for that image; its on-screen messages and restart sequence differ from an ordinary Gnarlyr update.
